You own only backend/screwit/codegen/, backend/tests/codegen/, deploy/codegen-sandbox/. Create nothing elsewhere.

Goal: the user can ask for parts that no template covers ("a bracket that holds this pipe to the wall", "a cap with a 3 mm drain hole", "a hook shaped like an S"), and Claude designs a NEW shape as CadQuery code. Because that code is untrusted, it only ever runs inside a disposable, locked-down container.

Build:
1. deploy/codegen-sandbox/Dockerfile: minimal image with Python 3.12 + CadQuery + trimesh pinned, a non-root user, a tiny runner `runner.py` that reads one JSON job on stdin ({"source": str, "params": {...}}), executes `build(params) -> cq.Workplane` with only the CadQuery API in scope, exports STL and STEP into /out, prints a JSON summary (volume, bbox, watertight, errors with traceback). Build it here with docker and record the image digest.
2. codegen/sandbox.py: run a job with `docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges --user 65534:65534 --pids-limit 128 --memory 1g --cpus 1 --tmpfs /tmp:size=64m -v <fresh per-job host dir>:/out:rw -i <image>`, a wall-clock timeout (30 s, then `docker kill`), nothing else mounted (no repo, no data dir, no home, no env passthrough, no secrets). Before running, an AST pre-check rejecting imports other than cadquery/math and any dunder attribute access, as a convenience filter only (the container is the boundary; say so in a docstring). Return the files and summary, or a structured error.
3. codegen/designer.py: the "try around" loop. Given a natural-language request, the target part's preferred measurements (mating dims must be caliper or user_confirmed, same rule as SPEC 6.3), and printer profile limits: ask Claude (via screwit.llm) for K=3 diverse candidate programs in parallel (different design approaches), run each in the sandbox, repair failures by sending the traceback back (up to 3 rounds per candidate), score the survivors (builds, watertight, fits build volume, required dims within tolerance of the request, wall thickness above the profile minimum, fewest overhangs), then render a preview PNG of the best two and send them back to Claude (vision) asking it to pick or refine once more. Return the winner plus a short design rationale and the other candidates' scores. All prompts object-agnostic. A deterministic fake LLM (SCREWIT_LLM=fake) returns canned programs, including one that fails first and is repaired, so the whole loop is testable here.
4. codegen/__init__.py: `design(request: str, part, params_hint: dict, profile, storage, out_prefix) -> (CadFiles-like dict, rationale, attempts)`; integration wires it into P5's CadService codegen branch and P4's create_cad tool.
5. Tests (must run here, Docker is available): the sandbox blocks network (a program that tries `socket` is rejected by the AST check, and a variant that evades the check still cannot connect inside the container), cannot read the host (no repo files visible inside), is killed at the timeout, cannot write outside /out, and runs as uid 65534; a valid program produces a watertight STL with the expected bbox; the designer loop with the fake LLM picks the passing candidate and records the repair. Mark the docker-dependent tests to skip cleanly if `docker info` fails.

Never run LLM-written code outside the container, not even in tests. Report also: image digest and size, measured sandbox start-to-finish time per job, and every isolation property you verified by test.
