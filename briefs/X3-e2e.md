# X3 end-to-end test suite (worktree screw-it-wt/e2e, branch ws/e2e)

Read: briefs/common.md, AGENTS.md (servers on 127.0.0.1; Next on :3000 proxies /api to FastAPI on :8000; no bearer token), SPEC.md 1.4, 4, 4.8, 5, 8, 9, and briefs/P1-web.md and briefs/P4-platform.md (what the other teams are building).

You own only e2e/ (top-level) and backend/tests/integration/. Create nothing elsewhere.

Purpose: the five teams each test their own part. You write the tests that prove the parts work together, ready to run as soon as their branches merge. Write against the public surface only: the HTTP routes in SPEC 5, the SSE wire format in backend/screwit/contracts/sse.py, the contracts, and the fixtures. Do not depend on any team's internal module names except the documented entry points `python -m screwit.app` (FastAPI, env SCREWIT_MODE=mock|live) and `npm run start` in web/.

Build:
1. backend/tests/integration/: pytest that starts `python -m screwit.app` with SCREWIT_MODE=mock on a free loopback port as a subprocess (skip with a clear reason if the module does not exist yet), waits for readiness, then exercises every SPEC 5 route over real HTTP with httpx: demo-scans, scan, reconstruction (signed asset URLs fetchable and returning real bytes), parts, scene-graph, measure, patch (revision bump; label-only patch no bump), merge, scale (409 on stale revision), cad POST/GET (stale after a patch to the mated part), chat SSE for both hero scans (decode every frame with contracts.sse.decode_chat_event; the trap conversation ends with repair_plan and parts_to_buy cards; the knob conversation asks for the shaft size first, then a cad_result card after a numeric reply), progress SSE (keep-alive comments tolerated). Validate every JSON body against the contracts. Also assert the listener is 127.0.0.1 only (read /proc/net/tcp or `ss`), and that a request from a non-loopback source address is refused if you can construct one (e.g. bind the client to another local address on the host if available; otherwise skip with reason).
2. e2e/: Playwright (pinned, chromium headless; install browsers into $KIROCREW_SCRATCH or the default cache) tests that start FastAPI mock mode and `npm run start` in a given web dir (env WEB_DIR, default the main tree's web/), then: landing shows both demo scans; the trap workspace loads, the status bar shows all stages done, the parts panel lists tailpiece, J-bend, slip nut, slip-joint washer; sending "it's leaking under here" renders a repair plan with 4 steps and a parts-to-buy card; the knob workspace: "make me a replacement knob" -> question about the shaft size -> "6 mm" -> CAD result card with required checks passing. Use text and ARIA roles, not CSS classes, so the tests survive styling changes; where a stable hook is needed, list the data-testid names you need in your report rather than guessing. Capture a screenshot per step into e2e/artifacts/ (gitignored) when run. Skip with a clear reason when web/ or the API module is missing.
3. A single runner script e2e/run_all.sh that runs both suites and prints a summary.

Until the other branches merge, most tests will SKIP. That is expected: make sure they skip cleanly (never error) and that the parts that do not depend on other teams pass (contract and fixture checks, SSE decoding of fixture scripts, the runner itself). Run them and report the skip reasons.

Report also: the data-testid names you need from P1, if any.
